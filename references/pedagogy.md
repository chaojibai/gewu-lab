# 探究结构与多表征：课件的教学设计层

渲染层管"像不像、对不对"，本文管**怎么教**：步骤按什么序列展开、现象用几种
表征呈现、控件怎么"藏"着引导。原则对本项目课件语境重写，与 detail-rules
的器材细节层互补。

## 一、仿真设计七则

1. **让不可见的可见**。离子、分子、场、热运动这些"看不见的主角"给可见形体
   （微粒场景、矢量线、云雾），让因果有画面可指。
2. **多表征同屏**。同一现象至少两种表征并列：3D 画面 + 曲线图/数轴/表格。
   现象在画布，规律在旁边——滴定课不能只有液面变色，pH 曲线要同步画出来。
3. **隐式引导**。想让学生先探索什么，就**只给那几个控件**；用控件的多少、
   限位的松紧来引导，不用大段文字指令。规则藏在 UI 里，不写在说明里。
4. **测量工具化**。读数做成仿真内的仪器——量筒、pH 计、温度计、秒表，
   可拖可读，学生"测量"而不是"被告知"。
5. **参数取真实值**。范围用真实世界的量（常见浓度、体温、室温、海平面气压），
   超出常识范围的滑杆会教出错误直觉。
6. **一鱼两吃**。课件结构支持两种用法：新课跟着步骤走，复习进自由沙盒
   （所有控件解锁）。步骤页和沙盒共用同一状态，不另起炉灶。
7. **即时反馈**。每次交互 100ms 内有可见后果；因果之间隔太久，探究就断了。

## 二、步骤序列：兴趣曲线

1. **钩子开场**。第一站是一个不需要前置知识的可玩瞬间或悬念问题
   （"不加搅拌，晶体真的不化吗？"），先让人爱上这个问题，再开始攀登。
2. **机制分解，先分后合**。把系统拆成小机制，**单独教**再组合：
   先 A（倾角影响流速）、再 B（温度影响溶解）、然后 A+B 的组合关卡。
   直接上全系统 = 只有先修过的人能玩。
3. **结尾沙盒**。最后一站是自由摆弄场，且只有用上全部学过的机制才玩得转
   ——结尾本身检验学习成果。
4. **内容门槛**。未到的步骤不给控件、不给数据；适度扣留反而让人学得更多
   （铺得太开等于没有重点）。

## 三、让学生自己造数据点

- 在"参数—结果"平面上让学生**留下自己的点**：每滴一次、每调一次参数，
  图上多一个点。点够了，规律（突跃、平台、正弦）自己浮出来——
  自己发现的数据比喂给的曲线记得牢。
- 把"课后题"嵌进课件本身：答案只有操作过才看得懂，而不是切到答题页。

## 四、Do / Show / Tell 各司其职

| 任务 | 最合适的载体 |
|---|---|
| 高度抽象的概念、定义 | 文字（面板讲解） |
| 宏观关系、趋势 | 图线、图表 |
| 时间维度的关联 | 动画 |
| 过程、系统、因果网络 | 3D 交互 |

**别用 3D 交互解释一切**。四者叠加使用并互相引用：面板文字提到哪个量，
画布里那个量就高亮；画布上发生了什么，面板读数就跟着变。

## 五、验收：真人过一遍

自检替代不了真人。请学生或同事完整过一遍课件，只看三件事：
哪里被跳过（钩子失效或门槛太低）、哪里卡住（反馈缺失或引导不明）、
结尾沙盒有没有人真的玩。跳过率高的步骤，先怀疑设计而不是怪用户。
