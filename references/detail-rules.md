# 细节修改规则（小件可读性 / 特写自检）

这一份是"大面看着行、凑近一看就假"的问题库。**每条都给出诊断信号 → 原因 → 修法**，
改完用 `scripts/views.js` 的 `detail` 机位复检。

---

## 一、小件"三件套"原则

玻璃小件（滴管、玻璃棒、温度计、细导管、量筒）在**浅背景**上几乎必然隐形，
因为它们的轮廓只占 1–2 px、颜色又接近背景。判据：

> 如果一件器材**只剩一个彩色部件**可见（如滴管只剩红色胶头），说明管身已经隐形。

修法 = 三件套齐活，缺一不可：

| 件 | 做法 | 参数 |
|---|---|---|
| 形体 | 不透明度 ≥ .55 的玻璃 + **两条母线**（`LineSegments`） | `0x6b8ca8`、opacity .7 |
| 内容 | 管内**有东西**：液柱 / 芯线 / 刻度 | 液柱 `0x9fc4dd`、opacity .75–.85 |
| 连接 | 端部**连接件**：橡胶头、金属环、支架夹 | 与主管同色系但更暗 |

反例（本项目的真实翻车）：滴管只有胶头可见 → 加"管内水柱 + 管口钢环 + 两条母线"后才读得出来。

## 二、放置与朝向（穿模/悬浮）

**判据：任何器材都必须"有支撑、有对接"**。悬空、错位、指向外，都是错误。

- 滴管/移液管：**尖端必须落在容器口的内接圆投影内**（横向偏移 ≤ 0.5r），
  且尖端在口沿**上方 0.5–2 单位**（不要悬到 5 单位以上，也不要插进液体里）
- 倾角 **≤ 15°**，尖端朝下；倾角过大看起来像"戳"进去
- 玻璃棒：一端必须**浸入液面以下**，另一端露在杯口外 2–4 单位
- 量筒/试管：底部必须有**底座或杯垫**；立不稳就要加接触阴影
- 夹持件（铁夹、管夹）：必须**真的咬住**被夹物（环心 = 管轴）

---

## 三、刻度与液面

**判据：刻度和液面必须是同一套坐标算出来的。**

- 刻度贴图（`CanvasTexture`）画在 **1.0 宽的平面**上时，**四周要留 6–8 px 透明边**，
  否则平面边界会在筒身上显出一个"卡片矩形"（本项目踩过：数字 72px 起画、刻线画到 128 边，
  结果右侧露出直边）
- `alphaTest` 用 **0.1–0.2**（太低留半透明底，太高把细刻线削掉）
- 刻度平面的 `renderOrder` 要**高于液体**（否则被液面盖住），并在 `z = r*0.96` 处（贴着前壁）
- 液面高度 = `vol / capacity × 有效高度`，**同一个函数**同时驱动液柱和液面片，
  不要两处各写一份（会错开）
- 液面要有**凹液面亮环**（`LineLoop`，白 .55）+ 一点高光；纯平色圆盘会被读成"塑料盖"

## 四、特写自检清单（每次改完 detail 机位逐条过）

```
[ ] 每个小件都能看出"它是什么"（不是只剩一个彩色块）
[ ] 没有悬空件：底有支撑、口有对接、夹有咬合
[ ] 刻度/数字不被滴管、瓶口、标注遮挡
[ ] 液面落在刻度区间内，且有亮环
[ ] 透明件边缘有 1px 深色轮廓（不是一团白）
[ ] 金属件有高光（不是灰片）
[ ] 标注不压器材（侧视/俯视都要看）
```

## 六、反例 → 正解（可直接引用为案例）

| 画面症状 | 真实原因 | 修法 |
|---|---|---|
| 滴管只剩一个红球 | 管身透明 + 无母线 + 无内容物 | 三件套（母线/液柱/钢环），opacity→.62 |
| 滴管"戳"在量筒外壁 | 尖端横向偏移 > r，倾角 -16° | 尖端移到口内 ±0.5r，倾角 ≤15° |
| 量筒身上有一块矩形 | 刻度贴图无留白、alphaTest 太低 | 四周留 8px 透明边，alphaTest .15 |
| 液面像个塑料盖 | 只有平色圆盘，没有凹液面亮环 | 加 `LineLoop` 亮环 + 液面高光，alpha 降到 .74 |
| 玻璃棒看不见 | 与滴管同病 | 淡蓝玻璃 .62 + 亮芯线 `.055` 半径 |
| 读数显示 92.4 mL 而目标是 94 | 读数直接读了补间中的状态 | 补间时存 `state[k+'T']`，面板读目标值 |
| 液体换了高度却不显示 | 液位用 `scale.y`，但液体渐变按世界高度算 | `K.setLiquidLevel(mesh, h, y0)` 同步 `uBot/uTop` |
```

## 七、节奏建议

细节修改**不要一次改十处**。按这个顺序，每轮只动一类：

1. 比例与位置（先让所有东西站对地方）
2. 可读性三件套（让每件都能被认出来）
3. 接触与穿插（底座、口沿、夹持）
4. 刻度/液面/读数一致性
5. 材质与光影（最后才调，前面没对时调材质是白费）

## 八、遮挡 / 断肢检查（"下半截不见了"）

**判据：任何一件器材，在特写里都不允许"断成两截"。**

真实原因通常不是几何缺失，而是**被同色背景或前层玻璃吞掉对比**：

| 症状 | 真实原因 | 修法 |
|---|---|---|
| 滴管只剩上半截 + 胶头 | 玻璃管高透（opacity .55~.6）压在**亮窗/亮墙**前，中段与背景亮度差 <8/255 | 管身两侧加暗边母线（`0x6b8ca8`、.7）；降低不透明度阈值到 .62–.68；管内加液柱 |
| 器材中段"消失" | 被 `glassCyl` 的 **BackSide 光晕**挡住（halo 在浅背景就是一块白卡） | 该器皿传 `noHalo: true`，或把 halo opacity 降到 ≤.32 |
| 器材被刻度/标签切片 | 刻度面、标注面 `renderOrder` 太高且不透明 | 刻度面 `alphaTest .15`；标注不压器材；必要时给器材 `renderOrder` 提高一层 |
| 细杆穿墙式消失 | 细长件 `depthWrite:false` + 前后两层玻璃 | 细杆单独 `renderOrder = 8`（最后画） |

### 采样判定法（不靠眼）

```js
// 沿器材主轴取 5 个点，读帧缓冲像素，与同高度的背景像素比亮度
// 中段任一点 |L - Lbg| < 8 → 判"被吞"，必须修
node scripts/pick.js courses/x.html "480,300;480,340;480,380;480,420;480,460"
```

### 修完的验收动作

同一机位、同一 clip 区域，前后各截一张并排看：**器材轮廓必须从头到尾连续**，
且与背景之间有可辨的边缘（不是"颜色渐变过渡"）。

## 九、这次的两个真实案例（可直接复述给用户）

1. **滴管只剩红胶头** → 管身 opacity .55 无母线 → 加到 .62 + 两条 `0x6b8ca8` 母线 + 管内水柱 + 管口钢环，并把滴管 `renderOrder=8`；同时量筒 `noHalo:true`（它的背面光晕是一块白卡，正好压在滴管中段）。
2. **量筒身上一块白矩形** → 不是刻度贴图，是 `glassCyl` 的 BackSide 光晕（opacity .5 的浅蓝壳在浅背景上读成白板）。降 opacity 到 .32 + 关键器皿关 halo。

## 十、火焰与发光体（最容易"洗白"的一类）

浅色背景 + 火焰，是本站踩坑最多的地方。**四条铁律，违反任何一条都会得到"一团白雾"**：

| 铁律 | 原因 | 做法 |
|---|---|---|
| **1. 必须 NormalBlending** | 加法混合会把橙色叠到 (255,255,255) 饱和 → 全白 | `SpriteMaterial({ blending: NormalBlending })`；只有深色场景才用 Additive |
| **2. 纹理主体 alpha 要实（≈1）** | alpha .5 的橙叠在白底上就是"淡橙薄纱" | 色带 `rgba(...,1)`，只在最后 6–10% 做渐隐 |
| **3. 羽化用 blur，不要用径向遮罩** | 径向遮罩圆心/半径没算准会把火焰顶部整段裁掉（本项目踩过：圆心 y=300、半径 252，顶点距 284 → 顶部 alpha=0） | 复制到临时 canvas → `ctx.filter='blur(2.5px)'` 重绘 |
| **4. 保持纹理原始宽高比** | 缩放公式里乘 `(2 - flick)` 会把火焰纵向拉长近一倍，色带被拉散成一片米黄 | `高 = base * 2.6 * (2-flick) * 0.62`，宽 `base * 1.4`（≈1:2） |

**还有一条：火焰只允许一个驱动源。**
引擎的 `updateFlames` 已经在改 `opacity / scale / light`，课程里再手写一套就会互相覆盖，
表现为"颜色一会儿浓一会儿淡、大小乱跳"。课程只负责 `flame.lit = true/false` 和 `position`。

色带参考（蜡烛，按纹理纵向 0=底、1=顶）：

```
0.00 – 0.18   蓝   rgba(88,148,255)      焰心：石蜡蒸气，不燃烧
0.18 – 0.30   白黄 rgba(255,246,206)      内焰：最亮
0.30 – 0.85   橙   rgba(255,116,14) → rgba(232,74,8)   外焰：主体
0.93 – 1.00   渐隐到 alpha 0
```

酒精灯把蓝段加宽到 0.42、橙色整体偏淡蓝；喷灯几乎全蓝锥。

## 十一、器材"入场动线"（不要用淡入假装出现）

**判据：一件器材不该凭空淡入。它一开始就应该在桌上，用到时被"拿过去"。**

用户对这点极其敏感——"突然出现个烧杯一下扣上去了"是不符合生活常识的。

做法（本项目的标准形态）：

1. **开场把全课要用的器材都摆出来**，各自记一个 `HOME` 坐标（备料区：台面右后方或前方留白处）
2. 每个"动线"用一个 0→1 的进度量驱动，**不要用 `visible` 开关**：

```js
var HOME = { hood: [11.6, .05, 4.6], stick: [-3.0, .30, 5.4], probe: [2.2, .34, 5.2] };

function ease(cur, target, sp, dt) { return cur + (target - cur) * Math.min(1, dt * sp); }

s.hoodIn = ease(s.hoodIn || 0, s.hood > .5 ? 1 : 0, 2.6, dt);
obj.position.set(
  HOME.hood[0] + (useX - HOME.hood[0]) * s.hoodIn,
  HOME.hood[1] + (useY - HOME.hood[1]) * s.hoodIn,
  HOME.hood[2] + (useZ - HOME.hood[2]) * s.hoodIn
);
obj.visible = s.hoodIn > .02;      // 只有"在备料区"和"已到位"之间切换才用可见性
```

3. 速度：重物（烧杯）2.6/s，小件（探针/火柴）3.2–3.4/s；到位后**不要瞬间吸附**，缓动本身已经收尾
4. 需要弧线时用 `K.moveTo(obj, to, dur, {arc:.35})`（内部走 sin 弧线，像"被手拿过去"）
5. **状态复位**：每步 `apply()` 先 `reset(s)` 清掉上一步的器材状态，否则会出现"上一步的火柴梗跟着进了下一步"
6. **备料区常驻可见**：判断可见性时**不能用动线进度**（`visible = hoodIn > .02` 会把进度为 0
   的备料器材全部藏掉——器材"不齐全"就是这么来的）。它们本来就该在桌上
   （探针、火柴梗、大型装置都算；只要备料位不穿模，就一律常显）
7. **备料区坐标要和"讲解面板遮挡区"一起规划**：课程 UI 面板通常占屏幕右侧 25–30%，
   对应世界坐标里靠 +x 的区域。备料区放那里等于白摆

反例：本项目第一版用 `K.fadeShow(烧杯)` 让烧杯"淡入"到蜡烛上方——用户直接判定"假"。

## 十三、温度探针/细杆类器材的辨识度

细长金属杆在浅背景上的问题和玻璃管一样（太细 + 无特征）。辨识三要素：

1. **材质特征**：拉丝钢（`roughness .22, metalness .95, envMapIntensity 1.4`），
   半径 ≤.05 —— 细才有"探针感"，粗了像铁棍
2. **结构特征**：白瓷绝缘环（探针/温度计的标志性部件）、银灰感应球（温度越高泛红：emissive 随温度）、
   短橡胶手柄 + 圆头
3. **备料姿态**：`rotation.y = 90°` 让杆朝向镜头方向，**不要横着伸**——横杆会穿过/压住其他器材

烧焦的小件（火柴梗）另见第十二节；**炭化段的坐标必须落在木条内部**，
从端点往外排会悬空（本项目踩过：`±(2.1 + ci*.44)` 错，`±(1.85 − ci*.42)` 对）。

## 十二点五、道具的"颜色语义"与动线节奏

**1. 颜色是身份。** 红色 = 火焰 / 火柴头 / 火，别的器材不许占用：
温度探针的感应珠做成红球时，用户直接把它当成火柴（真实投诉）。
探针珠保持银灰金属，温度只体现在微弱 emissive 上。

**2. 点燃过程要"演"出来。** 蜡烛不是"突然亮了"——应有一根火柴从火柴盒移到烛芯、
带着小火焰、蜡烛被引燃后火柴熄灭移回。关键代码形态：

```js
s.matchIn = ease(s.matchIn || 0, s.matchUse ? 1 : 0, 2.2, dt);
grp.position.y += Math.sin(Math.PI * mIn) * .9;      // 提起来
grp.rotation.z = Math.sin(t * 5.2) * .05 * Math.sin(Math.PI * mIn); // 被捏着的微晃
matchFlame.setLit(mIn > .85 ? 1 : 0);                // 到达烛芯才燃
if (mIn > .8) s.lit = 1;                             // 蜡烛被引燃
```

**3. 动线要"拿起 → 平移 → 放下"三段感。** 纯直线匀速插值 = 机械。
叠加 `sin(π·t)·lift`（lift 0.9–1.6），移动中给 rotation.z 一点 sin 摆动，
观感立刻从"机械完成"变成"被人操作"。

**4. 实验台必须"落地"。** 台面下要有柜体/桌腿且颜色够深（浅灰柜体在白背景里隐形，
用户会认为桌子悬空）。四角深灰钢腿 + 踢脚 + 加深柜门，相机 pitch ≥ .28 时应能看到。

**5. 火焰：sprite 到头就用几何体。** 一张 canvas 贴图做不出火的剪影，只能得到"光斑"。
最终形态是 **Lathe 旋转体 + 高度色带着色器**（见 render-recipes 末节）：
底部蓝 → 白黄 → 橙 → 顶端羽化，加 `uTime` 摇曳与呼吸缩放。红色只属于火。

## 十二、小件材质：火柴梗这类"有纹理的木头"

圆柱 + 纯色 = 塑料棒。真实火柴梗：

- **截面是方形**（`BoxGeometry(4.2, .16, .16)`），不是圆柱
- **木纹**：沿长度方向 2 条极细的浅色刻线（`.012` 见方），比贴图省事
- **烧焦过渡**：**不要做成分段纯色块**。早期版本用三段 `0x6b4a2c → 0x3b2a1c → 0x1b1512`
  靠 `visible` 逐段点亮，段与段之间是硬边，用户直接指出"过渡没有体现"。
  正解是**沿长度方向的 CanvasTexture 连续渐变**（见第十七节）
- **位置**：炭化前沿的推进量要落在木条**内部**；写成 `±(2.1 + ci*0.44)` 会跑到木条外面悬空（本项目踩过）

## 十四、NaN 污染：整个场景变黑（本项目最隐蔽的一个坑）

**症状**：某一节课突然"大面积黑屏"，但别的课正常；控制台无报错；材质参数看不出问题。

**根因**：某个光源的 `intensity` 变成了 **NaN**。three 计算 PBR 光照时，
`NaN` 会污染所有 Standard/Physical 材质的着色结果 → **全场 PBR 材质变黑**，
而 MeshBasicMaterial（不受光）依然正常 —— 于是表现为"背景黑、物体只剩轮廓线"。

**NaN 的典型写法**（我在本项目犯过）：

```js
// 错：右侧先求值，此时 s.flameLv 仍是 undefined → (fv - undefined) = NaN
s.flameLv = (s.flameLv === undefined ? 0 : s.flameLv) + (fv - s.flameLv) * k;

// 对：先取值到局部变量，再运算
var v = s.flameLv === undefined ? 0 : s.flameLv;
s.flameLv = v + (fv - v) * k;
```

**防御**（引擎层）：

```js
if (!isFinite(v)) v = 0;              // setLit / 任何写入 intensity、opacity 前
```

**排查手法（下次遇到黑屏按这个顺序，10 分钟定位）**：

1. 对照实验：把同引擎的**另一节课**截图 → 正常 ⇒ 是本课代码，不是引擎
2. 禁用本课的 `update` → 若恢复 ⇒ 问题在每帧更新里
3. 隐藏材质分组 → 若隐藏某类材质恢复 ⇒ 该类材质有毒
4. 打印灯光 `intensity` → **`isFinite()` 检查**，NaN 立刻现形

**教训**：任何写入 `intensity / opacity / scale` 的地方，先 `isFinite` 兜底；
框架级工具函数（setLit 等）应自带防护，不要指望每个调用点都写对。

## 十五、"过程"类实验必须画出**通路**，不能只演结果

典型投诉（原话）：「把气体通入澄清石灰水的过程没有体现」——
画面里只有一杯水自己变白，中间"气从哪来、怎么进去"整段是空的。

**判据：教材里凡是出现「通入 / 滴入 / 加热至 / 振荡 / 过滤 / 引流」这类动词，
画面上必须有承载它的物体与运动。**只演"前后两个状态"就是"仿假"。

标准形态（蜡烛燃烧产物检验 CO₂，可直接照抄结构）：

| 环节 | 组成 | 做法 |
|---|---|---|
| 气源 | 倒扣玻璃漏斗罩在火焰上方 | `CylinderGeometry(.2, R, h, 36, 1, true)`（上小下大）+ 口沿 Torus |
| 支撑 | **铁架台**：圆角底座 + 立杆 + 横臂 + 抱箍 + 紧固螺帽 | 悬空的漏斗一眼假；底座要落在桌面空处 |
| 连接 | 乳胶管 `CatmullRomCurve3` + `TubeGeometry` | 半径 **≥.18**，太细在浅背景上根本看不见 |
| 末端 | 玻璃导管竖直穿过器皿口 | **出口必须埋在液面以下**（`tipY` 取液体底部附近） |
| 现象 | 导管口连续冒气泡 → 上浮 → 到液面破掉 | 见第十六节 |
| 结果 | 液体**由下往上**逐渐浑浊 | 颗粒按高度编号，编号即出现顺序 |

配套要点：

- **浑浊观感曲线用 `wk = pow(turbid, .6)`**：线性插值到 60% 时画面上还像清水，
  而真实石灰水一通气就很快发白。颜色/不透明度/颗粒数都走 `wk`，不要走 `turbid`
- 气泡是**扁球**（`scale(w*1.14, w*.84, w*1.14)`），上升中的气泡不是标准球
- 浑浊到满时气泡可见度要降下来（`× (1 - wk*.5)`）：浑了就看不见气泡，才是对的
- 横臂这类斜杆别手算旋转，写个两点连线工具：

```js
function armBetween(a, b, r, mat) {
  var dir = new T.Vector3().subVectors(b, a), len = dir.length();
  var m = new T.Mesh(new T.CylinderGeometry(r, r, len, 10), mat);
  m.quaternion.setFromUnitVectors(new T.Vector3(0, 1, 0), dir.normalize());
  m.position.copy(a).add(b).multiplyScalar(.5);
  return m;
}
```

## 十六、透明液体内部的物体会**整颗消失**（本项目最坑的一条）

**症状**：气泡 / 悬浮颗粒明明在场景里（调试脚本打印坐标、`opacity` 都正常），
画面上一个都看不到；把液体隐藏就全出来了。

**根因**：液体着色器 `depthWrite: true`。`renderOrder` 只决定**绘制顺序**，
管不了深度——物体在液体前表面之后，深度测试直接把它剔掉。
**只写 `depthWrite:false` 不够，必须 `depthTest:false`。**

```js
bubbleMat.depthWrite = false;
bubbleMat.depthTest  = false;    // ← 关键，否则被液体前表面整颗剔除
```

顺带第二条：**纯白半透明球在浅色液体上等于隐形**。要靠"亮边"而不是"白色"：

```js
new T.MeshPhysicalMaterial({
  color: 0xdcebf6, roughness: .02, metalness: .05,
  transparent: true, side: T.DoubleSide,      // 前后两个面叠出边缘
  clearcoat: 1, clearcoatRoughness: .03,
  envMapIntensity: 2.2, depthWrite: false, depthTest: false
})
```

浑浊颗粒同理：**颜色用灰白 `0xe9eff5`，不要用纯白**——白液 + 白颗粒 = 没有悬浮感。

## 十七、连续渐变不要做成分段硬切

典型投诉（原话）：「两端先变黑向里变浅的过渡没有体现」。

**错误做法**：把物体切成 N 段、每段一个纯色、靠 `visible` 逐段点亮。
段与段之间必然是硬边，而且顺序/时机一错就整体失真。

**正解：一张沿长度方向的 CanvasTexture，每帧重绘渐变**（256×8 就够）：

```js
// 两端各画一段由深到浅的渐变；末端 alpha 必须收到 0，才能自然融入底色
var g = ctx.createLinearGradient(endX, 0, endX + reachPx, 0);
g.addColorStop(0.00, 'rgba(20,15,12,' + a + ')');
g.addColorStop(.20, 'rgba(46,32,20,' + a * .93 + ')');
g.addColorStop(.48, 'rgba(104,72,42,' + a * .66 + ')');
g.addColorStop(.78, 'rgba(152,114,72,' + a * .28 + ')');
g.addColorStop(1.00, 'rgba(196,160,108,0)');
```

配套四条：

1. **`BoxGeometry` 的材质分组顺序是 `+X −X +Y −Y +Z −Z`**：
   ±X 是小端面 → 用纯色材质；四个长面（u 轴正好沿长度）→ 用渐变贴图

   ```js
   new T.Mesh(geo, [cap, cap, texMat, texMat, texMat, texMat]);
   ```

2. **用独立计时器驱动，不要用"进步骤就带初值"的量**。
   本项目踩过：`charK = burnT / 8`，而 `apply()` 里写了 `burnT = max(burnT, 6)`
   → 一进步骤就是 75%，直接跳到全黑，过渡一帧没演。
   改成 `charT`（**器材到位后才开始累加**，3.4 s 走完）
3. **值没变就别重画**，省掉每帧一次 canvas→GPU 的贴图上传：

   ```js
   if (Math.abs(reach - lastReach) < .9 && Math.abs(a0 - lastA) < .004) return;
   ```
4. **演完要"取出观察"**：火柴梗在火焰里被火光包住，渐变根本看不清。
   炭化完成后移到一旁，并配一个「重新演示」按钮

## 十八、备料区坐标要**实测屏幕占比**，不能靠估

世界坐标 → 屏幕位置不是线性直觉（透视 + yaw），"x 加 3 大概就到右边了"经常是错的；
更麻烦的是**右侧 UI 面板会吃掉画面 25–30%**，摆进去等于白摆。
（第十一节第 7 条只说了"要考虑"，这里给可执行的量法。）

**测量脚本**（临时用，量完删）：把包围盒 8 个角点投影到屏幕取 min/max

```js
const box = new THREE.Box3().setFromObject(group);
let x0=1e9,x1=-1e9,y0=1e9,y1=-1e9;
for (let i = 0; i < 8; i++) {
  const v = new THREE.Vector3(
    i & 1 ? box.max.x : box.min.x,
    i & 2 ? box.max.y : box.min.y,
    i & 4 ? box.max.z : box.min.z).project(camera);
  const px = (v.x * .5 + .5) * W, py = (-v.y * .5 + .5) * H;
  x0=Math.min(x0,px); x1=Math.max(x1,px); y0=Math.min(y0,py); y1=Math.max(y1,py);
}
// → x0/W, x1/W, y0/H, y1/H 就是屏幕占比
```

**目标区间**：整套装置占屏幕横 **62%–77%**、纵 **25%–80%**（贴着面板左缘）。

**面板位置换算**：面板在 >1100px 时占右侧 400px
→ 1800 宽窗口面板从 **77.8%** 起；1920 宽从 **79.2%** 起；1440 宽从 **72.2%** 起。
**先问清楚用户的窗口宽度再定坐标**，不然同一组坐标在宽窗/窄窗下表现完全相反。

**迭代方式**：先量一个值，再按"1 世界单位 ≈ 1.3~1.4% 屏宽"线性外推，量第二遍确认。

**大型装置放进备料区前先瘦身**：本项目把漏斗口径 2.2→1.75、
铁架台从蜡烛右侧挪到左侧，横向占地 9 → 6 单位，才塞得进右侧空位。
**瘦身优先于挪位**——挪位只会把它顶到面板底下。

## 十九、同一空间不许同时站两件器材

**症状**（用户原话）：「倒数第二步，烧杯和导管器具重叠了」——
`apply()` 里同时写了 `hood = 1` 和 `gasIn = 1`，而这两件都要占**火焰上方**那一块空间。

**判据：动手前先把每步"哪件器材占哪块空间"列一遍**，冲突的改成互斥切换，不要硬塞。

做法：给"结论/复习"类步骤配互斥按钮，而不是一次全开：

```js
controls: [
  { type:'btn', label:'① 看"水"的证据：罩干冷烧杯',  onClick: s => { s.hood = 1; s.gasIn = 0; } },
  { type:'btn', label:'② 看"CO₂"的证据：通入石灰水', onClick: s => { s.hood = 0; s.gasIn = 1; } },
  { type:'btn', label:'③ 判定并给出结论',            onClick: s => { s.judged = true; } }
]
```

**已经拿到的证据不要因为器材撤走而清零**：读数只由"是否检出过"决定，
不要跟着器材动线回退——否则学生一按切换按钮，结论自己消失了。
（做法：撤走器材时只把**网格的不透明度**清 0，保留状态量。）

## 二十、水面与大地貌（自然场景课必看）

这一节是水的天然循环那节课用掉一整天换来的，按顺序照做能省掉全部返工。

### 20.1 河与海必须是**同一张水面**

两张水面相交，交界处必然出现：接缝、薄色片、叠影、"被隔开"的感觉。调透明度、调颜色都救不了。

正确结构：**一张网格 + 一个水位函数**。

```js
// 每个顶点算一次水位；河道走廊内用沿程水位，其余用海平面
var inRiver = riverDist(x, z) < halfW(u) + 2;
var WL = inRiver ? Math.max(ramp(u), bed(u) + .38) : SEA_Y;
// 河口段把水位压到 SEA_Y（sstep(.90,.995,u) 混合），于是天然接上
```

只在 `WL > 地形` 的地方铺三角形。河、海之间没有"面与面"的交界，接缝在构造上就不存在。
`河宽/河口收尾/海面内伸` 这些参数可以全部删掉——它们只是为补两张面的缝而生。

### 20.2 岸线要**等值线裁剪**，不能按格子取舍

按"四角全在水下才铺、否则跳过"来判定，岸线只能沿格子走 → 放大后是一级级马赛克。
用 marching squares：四角算 `f = WL - H`，全正铺整格、全负跳过，**正负混合就沿 `f=0` 收多边形**
（位置、水位、颜色都按 `t = fa/(fa-fb)` 插值），再扇形三角化。岸线于是落在等值线上，
精度由地形网格决定，与水面网格无关。

配套两条：
- 水位比地形**抬 5–6cm**，让水的平滑轮廓盖住高度场自身的锯齿剪影；
- 水面用 `renderOrder 2`、`depthWrite:false`、opacity .94–.96；
  **不要加 `polygonOffset`**——它会在剖面边缘把水面糊到侧壁上。

### 20.3 高度场的着色（细网格下的三个坑）

1. **法线要解析算**：顶点是逐三角形新建的，`computeVertexNormals()` 只能得到"每片一个法线"，
   0.2 网格下整片山坡会变成一层织物。用中心差分：
   `n = normalize(-(hR-hL)/2dx, 1, -(hD-hU)/2dz)`，再把 `n` 写进 `normal` 属性。
2. **顶点色按顶点算**，不要按格子中心算：相邻格子各给一个颜色，陡坡上就是一条条竖纹。
   湿土/雪线这类叠加也按顶点做。
3. **没有 uv 的几何体不要挂 `normalMap`**：采样的是无效 uv，只会给坡面刷一层竖向条纹。

### 20.4 削平类操作必须带空间范围

`h = Math.min(h, 某高度)` 这种"挖渠/压平"写法，如果只在语义上想作用于某一段，
条件里必须带位置范围（例如 `x > c - 12`），否则会削掉整条线——
真实案例：河口通道没加范围，整条河连山体一起被压到海平面以下，山被切出一道深槽。

### 20.5 河口：滩面压平 + 一条固定宽度的通道

- 岸线附近 7 单位内把地形噪声压成一条干净缓坡（`h = h*(1-bd) + (SEA_Y+(c-x)*.11)*bd`），
  **不要给河道留例外**——留了例外，噪声就会在滩面上挖出小水塘、把岸线咬出缺口；
- 河床单独用一条**固定宽度**的通道穿过滩面：
  `h = min(h, SEA_Y - .85*(1-rd/3.6)^1.15 - .08)`，渠底压到海面之下；
- 滩面平整 + 窄通道，河口才会是"一条河汇进海"，而不是"一摊浅水"。

### 20.6 陡坡的光

`shadow.normalBias ≈ .16`（阴影贴图 2048 铺 190 单位，陡坡会自遮挡出放射状贝壳纹）；
主光 `bias ≈ -.0004`。

### 20.7 参考数值（实测可跑）

| 项 | 值 |
|---|---|
| 地形网格 | 460×340（0.2 单位），顶面约 31 万三角形 |
| 水面网格 | 0.30 单位 + 等值线裁剪 |
| 全场景 | ≈54 万三角形 / 776 mesh / 60fps（GTX1650 级） |
| 水面材质 | `MeshPhysicalMaterial`，`roughness .5 / specularIntensity .10 / envMapIntensity .35` |
| 水色 | 浅 `[48,138,172]` → 深 `[18,82,118]`（线性值需 `pow(c/255, 2.2)`） |

> 21.1 的"金箔课"是实验室环境的**同一套**样板（台面/窗/后期），可作为蜡烛课的补充参考；
> 但**器材与备料动线一律以蜡烛课为准**（它的 `HOME.xxx` 备料区是范本）。

### 21.0 自然场景（水循环课为样板）

- 河与海**必须是一张水面**：水位由位置函数给出，只在"地形低于水位"处铺三角；
  拆成两张面一定出现接缝、薄片、叠痕。岸线用等值线裁剪（marching squares），不许按格子全水/全陆。
- 地形：高度场精度 ≥0.2 单位；法线**按高度场解析计算**（中心差分），不要 `computeVertexNormals`；
  顶点色按顶点算，不按格子中心算。详见第二十章的实测数值。
- 水面比地形略抬 5–6cm（盖住锯齿剪影），透明度 .94–.96、`depthWrite:false`；
  水色按实际水深逐顶点插值（浅青深蓝），不能有硬色块。
- 远景要有**尺度层次**：山、林、云、日轮各占一档，别让整幅画面只有一种密度。
- 剖面要有沉积层与含水层（这是"地下水"能讲通的前提），剖面颜色不掺随机量（否则成竖条纹）。

### 21.1 实验室环境（蜡烛课 + 金箔课为样板）

- **桌子**：按真实学生实验台 240×60×76 的比例 → 世界尺寸 `TW 38 × TD 12 × TTH .7`。
  厚环氧台面（`K.rbox r=.14` 倒角）+ 台面下三块浅灰立板 + 前横梁；
  下层隔板 `y = -TTH - 5.4`，带后挡板、每侧再分一格；**六只深色脚垫**（`y = FLOOR+.25`）。
  **不要**再用 `K.bench` 那种柜体式台子——柜门挡住腿，正视图里像悬空板。
- **材质**：台面/立板各配一张 `grainTex`（灰 .70/.26/rep7、深 .60/.20/rep10），大平面再叠
  `normalTex(128, 1.0, 3)` + `normalScale ≈ .12`。纯色大平板一眼假。
- **落地**：设备底部加 `K.blob` 接触阴影（半径+1），这是"压"在台面上的关键。
- **背景**：`hideLabBackdrop()` 后自建——淡蓝天 CanvasTexture + 2×3 窗格（外框 + 中竖梃 + 两道横梃），
  z ≈ -20.9 / -20.5。纯白自发光板会露馅。
- **后期**：`META[slug]['postfx'] = True`（SSAO + UnrealBloom + ACES 终合）。
- **相机**：`cam = { ty: 1.4, dist: 27, tx: 1, yaw: .12, pitch: .44 }`。

### 21.2 器材（蜡烛课为样板）

| 类别 | 参数 |
|---|---|
| 玻璃 | `MeshPhysicalMaterial{ color 0xf2f8fc, roughness .05, opacity .3, DoubleSide, depthWrite:false, clearcoat .7, clearcoatRoughness .08, envMapIntensity 1.8 }` |
| 钢/金属 | `0xaab2ba, roughness .3, metalness .9, env 1.25`；精细件 `0xc7ced6, .22, .95, 1.4` |
| 陶瓷/白件 | `0xf2f5f8, roughness .5, metalness .05`；表面皿 `0xf0f4f8, .25, clearcoat .8` |
| 蜡/受热件 | `0xfbf6ec, .42, clearcoat .55` |

- **火焰**只用 `K.shaderFlame`（体积火）；Lathe 硬边火、贴图光斑都不要。
- **备料**：所有器材一开始就在桌面固定位（`HOME.xxx`），用到才移动，结束后归位；不许 `visible=true` 凭空出现。

- **尺寸**：小件要够胖（试管高径比 ≈5）；细杆靠"母线 + 管内容物 + 连接环"三件套读形体。

## 二十二、教学交互硬规则（颜色语义 · 守恒常亮 · 主滑块 · 模型边界 · 反例演示）

### 22.1 颜色即语义：已知/未知/结论固定用色，全页一致

学生靠颜色建立"这个数是什么身份"的直觉。约定**三个身份三种颜色，全页统一**：
已知量/输入参数一个色、未知量/待求量一个色、结论/验证通过一个色
（例：已知蓝、未知橙、结论绿）。3D 场景标注、右侧面板读数、公式里的同一数字必须同色；
同一页面里同一数字换色 = 语义混乱。色弱兜底：颜色之外必须带文字标签。

### 22.2 守恒量要"常亮"，参数乱动也要看得见它不变

守恒律（质量/电荷/物料/能量守恒）是课件最该教的东西，却常被埋在读数堆里。
规则：**守恒量做成常显徽标**——面板固定一行"总量 = xx"或场景常驻标签，
任何参数变动时实时重算。学生把所有滑块拖乱，看到它纹丝不动，守恒就"信"了。
只算不给看等于白算。数值在精度内的轻微浮动要如实显示并注明有效位，不许显示成死数。

### 22.3 单主滑块：一个参数动，全身跟着动

每课选**一个主参数**（时间、滴数、温度、角度……），滑块一动，位置/速度/读数/颜色
全部实时重算；播放/暂停/单步/重置/速度都为它服务。一堆各自为政的开关会让学生
不知道"动哪个才能看到想看的"。标准控制组：播放/暂停/单步/重置 + 主滑块 + 速度。

### 22.4 模型要"小而诚实"，边界要写出来

读数公式取**决定学生最关心的那个量的最少几条**，用真实常数，**每帧解算**
（不是预制曲线查表）。页面用一句话注明简化假设（如"本演示忽略离子强度对活度的影响"）
——声明边界不是示弱，是防止课件被当成精确仪器。常数必须给来源（教材/手册），不许拍脑袋。

### 22.5 反例演示：每课一个"做错了会怎样"

最有说服力的教学瞬间是**后果演示**，正解教操作，反例教判断：

- 把水倒进浓硫酸（而非酸入水）→ 局部暴沸飞溅的警示演示
- 滴定冲过终点 → 误差读数立刻变红
- 加热未垫石棉网 / 试管口朝人 → 正误对照

规则：反例必须**安全、可撤销、一键复位**；后果用夸张但不失真的视觉表达；
正例与反例并排对照，不单独渲染危险画面本身。

### 22.6 迷思先行：先写"学生最容易错成什么样"，再设计步骤

每课动笔前先用一句话写下本课的**迷思概念**——学生最常见的那个错误理解
（如"把开口方向和 a 的符号记反""以为所有不告诉陌生人的信息都不能分享"）。
课件的关键步骤、反例演示、当堂自测必须**对准这个迷思**：一个步骤要么澄清它、
要么暴露它，不为热闹而设。教学目标写成当堂可观测的行为（"能指出"“能算出"），
不写"理解""掌握"这类看不见的词。

## 二十三、面板与目录页的反"默认脸"清单

课件右侧面板、目录页最容易长成"AI 默认脸"。以下五条用于自检——**每条默认做法
在特定主题下可以合法使用，但不许不做选择就落上去**：

### 23.1 认识五张默认脸

1. 米白底 + 高对比衬线大标题 + 陶土橙点缀；
2. 近黑底 + 单一荧光绿/朱红点缀；
3. 报纸式细线分栏 + 全站零圆角；
4. SaaS 卡片阵：内容切成一模一样的圆角卡，统一圆角统一浅阴影，渐变当装饰；
5. 模板铬件：每个标题头上顶一个全大写眉标、元信息用中点串接、
   等宽字体当小标签、按钮文字后挂箭头。

自检法：把设计要点遮住，问"换成任何一个别的课题，这份版式要不要改？"
——不用改，说明它没在为**这门课**服务。

### 23.2 大胆只花在一处

一件东西做记忆点（一个视觉锚、一个标志性交互），其余全部克制收队；
交稿前照"出门前摘掉一件配饰"检查一遍，删掉不为内容服务的装饰。

### 23.3 结构即信息

编号、分隔线、眉标、分组框必须**编码真实内容关系**：内容真是序列才能标 01/02/03，
真是并列才用等分卡片。装饰性结构一律删。

### 23.4 动效只回应动作

用户触发的动效（展开、确认、参数变化）随便用——它展示了"什么变了"；
非触发的动效只允许一个编排时刻（如开场），每个卡片淡入上浮、处处悬停动效
是模板味的来源。

### 23.5 面板文案三则

- 按用户的语言命名："保存实验数据"而不是"提交表单"；
- 一个动作全程同名：点"开始滴定"，完成提示就叫"滴定已开始/已结束"，不许中途换词；
- 错误与空状态**指出路**：说明发生了什么、下一步做什么，用界面的语气，
  不道歉、不含糊、不抒情形。
